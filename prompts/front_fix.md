以下是针对排版修复和逻辑重构的完整建议：
一、 核心逻辑与布局重构建议 (UX/UI Refactoring)

目前的逻辑是：“结果摘要 -> 配置 -> 输入 -> 状态/结果”，这是反直觉的。
合理的交互逻辑应该是： “全局配置 -> 输入与参数 -> 执行 -> (过程中)系统状态监控 -> (结束后)结果与日志”。

我建议将页面重构为标准的**“左侧控制，右侧监控”或者是“上部配置，下部执行与监控”**的布局。
方案 A：左右分栏布局（推荐，适合宽屏）

将页面分为左右两大部分：

    左侧栏 (宽度 30% - 40%)：控制区

        模型与配置： 放置 当前模型、输入模式、Token 设置、Prefill 批量大小 等配置项。

        输入面板： 放置 Prompt 输入框。

        操作按钮： 醒目的 生成 / Run 按钮。

    右侧栏 (宽度 60% - 70%)：监控与结果区

        顶部：关键指标 (KPI Cards) —— 将“实验摘要”和“性能概览”合并，横向排列。

        中部：流水线可视化 —— 放置 Prefill 层划分 表格和系统状态（队列信息）。

        下部：硬件监控 —— 显存使用情况。

        底部：日志输出 —— 日志按钮或日志预览窗。

二、 具体排版修复细节 (UI Fixes)

针对你截图中出现的具体问题，以下是详细的修复方案：
1. 顶部“实验摘要”区域 (Section: Experiment Summary)

    问题： 标签和数值垂直排列，且每个指标独占一行，极其浪费纵向空间。

    修复：

        合并： 此区域的数据（完成请求、延迟、TPS）与下方的“性能概览”高度重合，建议直接删除此区域，将数据合并到下方的 dashboard 中。

        如果保留： 改为横向 Flex 布局。使用“统计数值卡片 (Statistic Card)”样式。

            样式参考： 灰色背景容器 -> 内部 4 个小卡片横向排列 -> 每个卡片上方是小字号灰色 Label（如“平均总延迟”），下方是大字号加粗 Value（如“39836 ms”）。

2. “PD 分离流水线”配置区

    问题： 表格（Prefill 层划分）被下方的三列布局遮挡/重叠，导致显示不全。

    修复：

        清除浮动/Flex 修正： 检查 .row 或父容器是否设置了固定高度。给表格容器加上 margin-bottom: 20px。

        折叠面板： “Prefill 层划分”这种配置信息如果是静态的，可以放入一个可折叠的 Collapse 面板中，避免占据核心视觉区。

3. 核心三列布局 (请求输入 | 系统状态 | 性能概览)

这是排版最乱的地方。

    左列 - 请求输入：

        问题： 模型路径太长可能撑破布局；按钮位置尴尬。

        修复：

            当前模型：如果路径过长，使用省略号（ellipsis）截断，鼠标悬停显示全称。

            Textarea：增加高度，让输入框占据该列剩余空间。

            生成按钮：宽度设为 100% (Block button)，并设置为高亮色（如蓝色），置于输入框下方。

    中列 - 系统状态：

        问题： 字段对齐不整齐，日志按钮像标签。

        修复：

            键值对对齐： 使用 <Description List> 或 Grid 布局。左边 Label (灰色)，右边 Value (黑色加粗)。例如：
            code Text

            进行中请求:  0
            Prefill 队列: 0

            日志按钮： 将 4 个日志按钮改为一组图标按钮，或者下拉菜单，不要散乱排列。

    右列 - 性能概览 (最严重的问题)：

        问题： 文字换行（如“平均 TPS (端... 到端)”），数值和单位分离，长数值导致布局崩坏。

        修复：

            强制不换行： 给 Label 设置 white-space: nowrap;。

            单位处理： 将单位 (ms) 放在数值后面，或者作为 Label 的一部分，不要让它挤占空间。

            数值格式化： 39836.86 这种数字太长。

                保留 1-2 位小数。

                如果是毫秒且数值很大，逻辑上自动转换为秒（39.84 s）。

            布局改为 Grid： 不要试图在一行里塞太长的 Label。

                建议样式： 一行显示一个指标，左侧 Label，右侧 Value（右对齐）。

4. 底部“节点显存使用”

    问题： 纯文本显示，不够直观。

    修复：

        可视化进度条： 在每个 IP 卡片中，引入一个 Progress Bar。

        颜色警示：

            < 50% 使用绿色。

                80% 使用橙色。

                90% 使用红色。

        网格对齐： 确保每张卡片高度一致（Equal Height）。

三、 视觉层级优化 (Visual Hierarchy)

为了解决“看起来很乱”的问题，需要建立视觉层级：

    背景区分：

        给整个页面一个浅灰背景 (#f0f2f5)。

        给每个功能区块（输入、监控、显存）一个白色的背景卡片 (#ffffff)，并加上轻微的圆角和阴影。这样能从视觉上把不同逻辑的模块分开。

    字体规范：

        标题： 16px - 18px，加粗，深色 (#333)。

        标签 (Label)： 12px - 14px，灰色 (#666)。

        数值 (Value)： 20px+，根据重要性加粗或使用等宽字体（Monospace），方便数字对齐。

总结

目前的界面最大的问题是信息展示控件的容器宽度不够以及重复的信息展示。

    删掉顶部的“实验摘要”。

    重写右下角的“性能概览”CSS，强制不换行，或者改用上下结构的统计卡片。

    整理三列布局，建议改为左右两栏，左侧专注输入，右侧专注输出。
